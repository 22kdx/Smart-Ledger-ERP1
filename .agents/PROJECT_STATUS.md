# سجل حالة مدار ERP والتسليم

آخر مراجعة: 2 نوفمبر 2026

## الهدف ونطاق المنتج

- نظام ERP عربي يدعم أنشطة تجارية وخدمية متعددة.
- أسواق البداية اليمن والسعودية، مع إعداد بلد كل منشأة وعملتها وأسعار الصرف من إعداداتها.
- تتضمن قائمة العملات الابتدائية YER وSAR وUSD، ويمكن إضافة عملات أخرى أو إيقافها دون حذف السجلات السابقة.
- لا تُجمع مبالغ بعملات مختلفة دون تحويل موثق.
- الهدف المهم للمستخدم: أن يستطيع مستخدمون مخوّلون العمل على بيانات المنشأة نفسها، حتى عند استخدام حسابات أو أجهزة مختلفة.
- أكد المستخدم أن كل قيمة تشغيلية متغيرة، مثل اسم المنشأة والبلد والعملة الأساسية والضرائب وأسعار الصرف والأسعار الأساسية، يجب أن تُختار من إعدادات المنشأة لا أن تُفرض كثابت.
- أكد المستخدم أن التطبيق يُكمل أولًا ثم يُنقل إلى VPS يملكه؛ الخادم الخاص هو مصدر البيانات الدائم، والتخزين المحلي cache/offline فقط.

## الحالة الحالية بحسب الكود

- تُعرض الأرقام دائمًا بالصيغة الإنجليزية (0–9)، بما في ذلك المبالغ والتواريخ والنصوص العربية والحقول والتنبيهات؛ تُحوّل الأرقام العربية/الفارسية للعرض والإدخال فقط دون تعديل السجلات القديمة.
- يوجد تطبيق جوال Expo عربي؛ يُفرض RTL على iOS وAndroid، ويُضبط جذر صفحة الويب إلى RTL. النصوص العربية تُحاذى لليمين عبر المكوّن المشترك، مع إبقاء الحقول الرقمية والتواريخ والرموز اللاتينية LTR لسهولة إدخالها.
- نموذج البيانات المحلي يشمل الفواتير، الأصناف، الإيرادات والمصروفات، القيود المحاسبية، الموظفين، جهات الاتصال، وإعدادات المنشأة والعملات والضرائب وأسعار الصرف.
- أُضيفت إلى إعدادات «المزيد» حقول البلد (رمز من حرفين)، العملة الأساسية، العملات المسموحة، قواعد الضرائب، أسعار الصرف مع تاريخ السريان ومصدر السعر، وتاريخ بداية السنة المالية (اليوم والشهر). لا يُختار البلد تلقائيًا ولا يُفرض تاريخ سنة مالية.
- قائمة العملات قابلة للإضافة والتفعيل/الإيقاف؛ لا يمكن إيقاف العملة الأساسية. القيمة الافتراضية SAR تخص بيانات العرض التجريبية الحالية ويمكن تعديلها من الإعدادات، ولا تُحوّل المبالغ المسجلة عند تغييرها.
- قواعد الضرائب قابلة للإضافة والتعديل والتفعيل/الإيقاف حسب المنشأة، لكن إعدادها لا يضيف الضريبة إلى الفواتير ولا يعتمد الامتثال المحلي.
- أسعار الصرف تُدخل يدويًا مع تاريخ ومصدر، ويُمنع تكرار الزوج والتاريخ. تسجيل السعر لا يغيّر المستندات القديمة ولا ينفذ التحويل المحاسبي تلقائيًا.
- التغييرات محفوظة محليًا عبر AsyncStorage على الجهاز/المتصفح المحلي، مع بقاء مفتاح `@midad-erp/local-v1`. تُرحّل نسبة الضريبة القديمة إلى قاعدة قابلة للتحرير، وتُضاف العملات الموجودة في السجلات القديمة إلى الخيارات دون تعديل تلك السجلات.
- توجد مواصفة API مبدئية للشركات والحسابات والقيود، ومخططات قاعدة بيانات.
- خادم API الحالي يضم مسار فحص الصحة فقط؛ لم يظهر أن التطبيق يقرأ أو يحفظ بياناته عبر API.
- طُبقت هوية الثيم Mizan Figma v1.2 على واجهة مدار الحالية: ألوان فاتحة/داكنة وخط Tajawal حديث للعربية وInter للاتينية، مع الحفاظ على الشاشات وسلوك البيانات الحالي. الوضع يتبع إعداد الجهاز تلقائيًا؛ لا يوجد اختيار يدوي محفوظ داخل التطبيق.
- لم يظهر في تدفق التطبيق الذي تمت مراجعته تسجيل دخول فعلي أو ربط المستخدم بعضوية منشأة. توجد حزمة Clerk ضمن الاعتماديات، لكن وجود الحزمة وحده لا يعني أن المصادقة موصولة. وبحسب قيد المستخدم، لا يجوز الاعتماد على مصادقة مُدارة خاصة بـReplit؛ يلزم تحديد حل قابل للنقل قبل التنفيذ.

## متطلبات الاستضافة وواجهة API المعتمدة

- يجب توحيد كل طلبات الشبكة في API client واحد، وقراءة `API_BASE_URL` من ملف إعداد وقت تشغيل واحد يمكن تغييره دون إعادة بناء؛ لا روابط خادم أو طلبات مباشرة داخل الشاشات.
- لا تستخدم قاعدة Replit أو Supabase أو تخزينًا سحابيًا لطرف آخر، ولا تعتمد في المنتج على نشر Replit التلقائي أو أسراره أو مساراته أو أي خدمة خاصة به.
- يجب أن يبقى التطبيق والخادم قابلين للنقل يدويًا إلى VPS المستخدم. التخزين المحلي cache/offline فقط، ولا يُعلن نجاح الحفظ قبل تأكيد الخادم.
- إلى أن يصبح VPS جاهزًا، تستخدم بيانات اختبار غير حقيقية فقط؛ لا تُدخل بيانات منشأة فعلية في خدمة سحابية لطرف آخر.
- ملف `README.md` مطلوب عند اكتمال التطبيق، ويجب أن يشرح البناء والتشغيل ودوال API client وحقول API المتوقعة وتغيير عنوان الخادم والنقل إلى VPS.
- هذه متطلبات معتمدة لكنها غير مطبقة بعد؛ لم يظهر API client موحد أو إعداد وقت تشغيل لـ`API_BASE_URL` أو `README.md` نهائي.

## نقطة التوقف

المشروع نموذج أولي بواجهة وإعدادات وبيانات محلية لمنشأة واحدة، وليس نظامًا متعدد المنشآت أو المستخدمين ببيانات سحابية مشتركة. مشاركة ملفات المشروع لا تزامن بيانات ERP المحلية.

مراجعة المحاسب المحلي للإطار المحاسبي ومتطلبات البلد والضريبة والتقارير ما زالت مؤجلة. لا تُستخدم قواعد الضريبة أو أسعار الصرف في حسابات الفواتير أو القيود حتى اعتماد طريقة الاستخدام المحاسبي.

## نتيجة المراجعة الحالية

- أكدت مراجعة الكود أن `erp-store` ما زال يقرأ ويحفظ عبر AsyncStorage بالمفتاح `@midad-erp/local-v1`؛ لم يُعثر على استدعاء API من مخزن التطبيق.
- خادم API ما زال يقدّم فحص الصحة فقط؛ لا يوصّل قاعدة البيانات أو وسيط Clerk، ومسارات الشركات والحسابات والقيود المذكورة في مواصفة OpenAPI لم تُنفذ في الخادم.
- مخططات PostgreSQL التمهيدية موجودة، لكن وجودها لا يعني أن التطبيق يحفظ فيها. لا توجد مصادقة فعلية أو مزامنة مشتركة مؤكدة.
- بعض المخططات الحالية ما زالت تقيد العملات بـYER/SAR/USD وتضع قيمة افتراضية للعملة الأساسية ومعدل الضريبة؛ يلزم تحويلها لاحقًا إلى إعدادات قابلة للإدارة دون تعديل السجلات التاريخية.
- المرحلة 0 غير مكتملة: نطاق الأسواق والأنشطة وإعدادات المنشأة موثق، لكن مصفوفة السياسات المحاسبية والضرائب والتقارير لكل بلد لم تعتمدها جهة مالية مختصة. لا يمكن إكمال هذه البوابة باستنتاج سياسات محاسبية.
- متطلبات المستخدم الجديدة للإعدادات والاستضافة وAPI والمصادقة القابلة للنقل موثقة في `ERP_ROADMAP_AR.md` و`ERP_SCOPE_AR.md` و`replit.md`، لكنها لم تُنفذ في الكود؛ لم يُنشأ README نهائي.
- لم تُغيّر هذه الدفعة التطبيق أو قاعدة البيانات أو بيانات المستخدم، ولم تُشغّل اختبارات لعدم وجود تعديل برمجي.

## الخطوات التالية المقترحة

الخطة المفصلة حسب الأولوية ومعايير القبول موجودة في `ERP_ROADMAP_AR.md`.

1. **المرحلة 0 قيد المراجعة المالية:** قرارات النطاق وإعدادات المنشأة موثقة وموجودة في النموذج المحلي؛ يلزم اعتماد محاسب محلي للسياسات ومصفوفة اليمن والسعودية قبل تفعيل الحسابات المحلية.
2. بعد المراجعة، افحص تكامل المصادقة الحالي، واختر حلًا قابلًا للنقل غير معتمد على Replit قبل إضافة الهوية وعضوية المنشأة وعزل البيانات.
3. قبل مشاركة البيانات بين المستخدمين أو الأجهزة، صمّم ترحيلًا ونسخة احتياطية من AsyncStorage إلى API/قاعدة بيانات VPS يملكها المستخدم؛ لا تستبدل البيانات المحلية ضمن هذا العمل ولا تستخدم خدمة تخزين خارجية.
4. قرر واعتمد محاسبيًا متى وكيف يُثبت سعر الصرف والضريبة على المستند، ثم نفّذ ذلك مع حفظ القيم المعتمدة دون تغيير المستندات القديمة.
5. أكمل المحاسبة الأساسية ودورات المبيعات والتحصيل والمشتريات والسداد والنقد والمخزون وفق أولوية المنتج.

## نتيجة آخر دفعة تحقق

- في دفعة الأرقام: ضُبط تنسيق المبالغ وتاريخ اليوم على الأرقام اللاتينية، وتحوّل النص المشترك والحقول والتنبيهات الأرقام العربية/الفارسية إلى 0–9. بقيت السجلات القديمة محفوظة كما هي.
- اجتاز `pnpm --filter @workspace/midad-erp run typecheck` واختبار التخزين المعزول `pnpm --filter @workspace/midad-erp run test:storage` بنتيجة 3/3، وكذلك `git diff --check`. عاينت الشاشة الرئيسية 390×844؛ ظهرت المبالغ والعدادات بالأرقام الإنجليزية، ولم يظهر سوى إشعار React DevTools المعتاد.
- لم يتغير مفتاح AsyncStorage أو أي ملف بيانات. التحويل يطبق عند العرض والإدخال، ولا يعيد كتابة البيانات المخزنة.
- في دفعة RTL: وُحّد اتجاه النص العربي ومحاذاته على مستوى مكوّن النص المشترك، وفُعّل RTL للتطبيق، وعُدّلت الصفوف كي لا تنعكس مرتين. الحقول الرقمية والتواريخ ورموز البلدان تبقى LTR عمدًا.
- استُبدل خط IBM Plex Sans Arabic بخط Tajawal، مع إبقاء Inter للنص اللاتيني. عُرّبت رسائل الخطأ وصفحة المسار غير الموجود.
- اجتاز `pnpm --filter @workspace/midad-erp run typecheck` و`git diff --check`، وأظهر إعداد Expo `supportsRTL: true`. بعد إصلاح توافق RTL مع React Native Web، عرضت معاينة 390×844 بشكل صحيح؛ لم يظهر في سجل المتصفح سوى إشعار React DevTools المعتاد.
- لم تتغير ملفات التخزين أو البيانات، وبقي مفتاح AsyncStorage `@midad-erp/local-v1` كما هو. اختبارات الحفظ المعزولة السابقة نجحت 3/3؛ لا تقرأ أو تكتب بيانات الجهاز/المتصفح الفعلية. لم يُجرَ تحقق تفاعلي على جهاز فعلي.
- بقيت الضرائب وأسعار الصرف إعدادات فقط، دون تطبيق على المستندات أو تحويلات تلقائية. لا يوجد ترحيل API أو مزامنة سحابية.
- **الخطوة التالية:** الحصول على اعتماد مالي موثق للإطار المحاسبي ومصفوفة البلد/الضريبة/التقرير/العملة في اليمن والسعودية. بعد ذلك تُراجع المصادقة الحالية وتُبنى طبقة API قابلة للنقل وملف إعداد `API_BASE_URL` وقت التشغيل، ثم تُصمم النسخ الاحتياطية وخطة ترحيل AsyncStorage إلى VPS المستخدم. لا تُمسح البيانات المحلية ولا تُفعّل الضرائب أو التحويلات قبل الاعتماد.
