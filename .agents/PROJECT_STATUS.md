# سجل حالة TAMM ERP والتسليم

آخر مراجعة: 3 نوفمبر 2026

## الهدف ونطاق المنتج

- نظام ERP عربي يدعم أنشطة تجارية وخدمية متعددة.
- أسواق البداية اليمن والسعودية، مع إعداد بلد كل منشأة وعملتها وأسعار الصرف من إعداداتها.
- تتضمن قائمة العملات الابتدائية YER وSAR وUSD، ويمكن إضافة عملات أخرى أو إيقافها دون حذف السجلات السابقة.
- لا تُجمع مبالغ بعملات مختلفة دون تحويل موثق.
- الهدف المهم للمستخدم: أن يستطيع مستخدمون مخوّلون العمل على بيانات المنشأة نفسها، حتى عند استخدام حسابات أو أجهزة مختلفة.
- أكد المستخدم أن كل قيمة تشغيلية متغيرة، مثل اسم المنشأة والبلد والعملة الأساسية والضرائب وأسعار الصرف والأسعار الأساسية، يجب أن تُختار من إعدادات المنشأة لا أن تُفرض كثابت.
- أكد المستخدم أن التطبيق يُكمل أولًا ثم يُنقل إلى VPS يملكه؛ الخادم الخاص هو مصدر البيانات الدائم، والتخزين المحلي cache/offline فقط.

## الحالة الحالية بحسب الكود

- تُعرض الأرقام دائمًا بالصيغة الإنجليزية (0–9)، بما في ذلك المبالغ والتواريخ والنصوص العربية والحقول والتنبيهات؛ تُحوّل الأرقام العربية/الفارسية للعرض والإدخال فقط دون تعديل السجلات القديمة.
- يوجد تطبيق جوال Expo عربي؛ يُفرض RTL على iOS وAndroid، ويُضبط جذر صفحة الويب إلى RTL. النصوص العربية تُحاذى لليمين عبر المكوّن المشترك، مع إبقاء الحقول الرقمية والتواريخ والرموز اللاتينية LTR لسهولة إدخالها.
- الاسم الثابت للنظام والتطبيق هو TAMM ERP، واسم المنشأة يُعرض من بياناتها بشكل مستقل. أُضيف شعار المستخدم بنسختيه المناسبة للوضعين الفاتح والداكن، وتم تحديث اسم التطبيق وأيقونته؛ لم تتغير بيانات المنشأة أو مفاتيح التخزين.
- نموذج البيانات المحلي يشمل الفواتير، الأصناف، الإيرادات والمصروفات، القيود المحاسبية، الموظفين، جهات الاتصال، وإعدادات المنشأة والعملات والضرائب وأسعار الصرف.
- أُضيفت إلى إعدادات «المزيد» حقول البلد (رمز من حرفين)، العملة الأساسية، العملات المسموحة، قواعد الضرائب، أسعار الصرف مع تاريخ السريان ومصدر السعر، وتاريخ بداية السنة المالية (اليوم والشهر). لا يُختار البلد تلقائيًا ولا يُفرض تاريخ سنة مالية.
- قائمة العملات قابلة للإضافة والتفعيل/الإيقاف؛ لا يمكن إيقاف العملة الأساسية. القيمة الافتراضية SAR تخص بيانات العرض التجريبية الحالية ويمكن تعديلها من الإعدادات، ولا تُحوّل المبالغ المسجلة عند تغييرها.
- قواعد الضرائب قابلة للإضافة والتعديل والتفعيل/الإيقاف حسب المنشأة، لكن إعدادها لا يضيف الضريبة إلى الفواتير ولا يعتمد الامتثال المحلي.
- أسعار الصرف تُدخل يدويًا مع تاريخ ومصدر، ويُمنع تكرار الزوج والتاريخ. تسجيل السعر لا يغيّر المستندات القديمة ولا ينفذ التحويل المحاسبي تلقائيًا.
- التغييرات محفوظة محليًا عبر AsyncStorage على الجهاز/المتصفح المحلي، مع بقاء مفتاح `@midad-erp/local-v1`. تُرحّل نسبة الضريبة القديمة إلى قاعدة قابلة للتحرير، وتُضاف العملات الموجودة في السجلات القديمة إلى الخيارات دون تعديل تلك السجلات.
- توجد مواصفة API للشركات والحسابات والقيود وإعدادات المنشأة والعملات وقواعد الضرائب وأسعار الصرف، ومخططات قاعدة بيانات لها. قوائم الأسعار لم تُنفذ بعد لأنها تحتاج ربطًا واضحًا ببيانات الأصناف والعملاء.
- خادم API يضم مسار الصحة والمصادقة الداخلية ومسارات المنشآت والعضويات وإعدادات المنشأة والضرائب وأسعار الصرف؛ لم يظهر أن التطبيق يقرأ أو يحفظ سجلات ERP عبر API.
- طُبقت هوية الثيم Mizan Figma v1.2 على واجهة TAMM ERP: ألوان فاتحة/داكنة وخط Tajawal حديث للعربية وInter للاتينية، مع الحفاظ على الشاشات وسلوك البيانات الحالي. الوضع يتبع إعداد الجهاز تلقائيًا؛ لا يوجد اختيار يدوي محفوظ داخل التطبيق.
- لا توجد شاشات تسجيل دخول حتى الآن. أُضيف عميل مصادقة محمول مستقل عن الشاشات؛ يحفظ refresh token في SecureStore على الهاتف ولا يضع رموز المصادقة في AsyncStorage.

## متطلبات الاستضافة وواجهة API المعتمدة

- يجب توحيد كل طلبات الشبكة في API client واحد، وقراءة `API_BASE_URL` من ملف إعداد وقت تشغيل واحد يمكن تغييره دون إعادة بناء؛ لا روابط خادم أو طلبات مباشرة داخل الشاشات.
- لا تستخدم قاعدة Replit أو Supabase أو تخزينًا سحابيًا لطرف آخر، ولا تعتمد في المنتج على نشر Replit التلقائي أو أسراره أو مساراته أو أي خدمة خاصة به.
- يجب أن يبقى التطبيق والخادم قابلين للنقل يدويًا إلى VPS المستخدم. التخزين المحلي cache/offline فقط، ولا يُعلن نجاح الحفظ قبل تأكيد الخادم.
- إلى أن يصبح VPS جاهزًا، تستخدم بيانات اختبار غير حقيقية فقط؛ لا تُدخل بيانات منشأة فعلية في خدمة سحابية لطرف آخر.
- ملف `README.md` مطلوب عند اكتمال التطبيق، ويجب أن يشرح البناء والتشغيل ودوال API client وحقول API المتوقعة وتغيير عنوان الخادم والنقل إلى VPS.
- أُضيف API client موحد وإعداد وقت تشغيل لـ`API_BASE_URL` يستورده المستخدم من ملف JSON ويحفظه محليًا على الجهاز. توجد مسارات API لملف المنشأة والسنة المالية والعملات المسموحة وقواعد الضرائب وأسعار الصرف، لكن التطبيق لا يستدعيها بعد. قوائم الأسعار ومزامنة بيانات ERP و`README.md` النهائي غير مكتملة.

## نقطة التوقف

التطبيق ما زال نموذجًا أوليًا لبيانات ERP محلية. توجد في الجوال قيود متعددة البنود مع المسودة والترحيل والعكس، ودليل حسابات وتقارير محاسبية أساسية. أضيفت خدمة محاسبية وعقود API في الخادم، لكنها ليست موصولة من التطبيق، ومسارات الحسابات والقيود ليست مفعّلة بعد.

مراجعة المحاسب المحلي للإطار المحاسبي ومتطلبات البلد والضريبة والتقارير ما زالت مؤجلة. لا تُستخدم قواعد الضريبة أو أسعار الصرف في حسابات الفواتير أو القيود حتى اعتماد طريقة الاستخدام المحاسبي.

**توجيه التنفيذ الحالي من المستخدم (3 نوفمبر 2026):** أكمل الوظائف داخل تطبيق الجوال أولًا، ولا تبدأ ربط التطبيق بالخادم أو مزامنته قبل اكتمال التطبيق وموافقة المستخدم. تظل بيانات الجوال محلية عبر AsyncStorage في هذه المرحلة.

## نتيجة المراجعة الحالية

- أكدت مراجعة الكود أن `erp-store` ما زال يقرأ ويحفظ عبر AsyncStorage بالمفتاح `@midad-erp/local-v1`؛ لم يُعثر على استدعاء API من مخزن التطبيق.
- يُهيّأ API client عند بدء التطبيق، وتتيح شاشة إعدادات الشركة استيراد ملف JSON والتحقق من عنوانه واختبار الاتصال بمسار الصحة. إعداد الاتصال منفصل عن بيانات ERP، ولا يعني أن مزامنة بيانات المنشأة قد نُفذت.
- خادم API يضم فحص الصحة والمصادقة الداخلية ومسارات المنشآت والعضويات، إضافة إلى إعدادات ملف المنشأة والعملات وقواعد الضرائب وأسعار الصرف. مخططات الحسابات والقيود موجودة، لكن مساراتها الفعلية ووحدات ERP الأخرى ما زالت غير منفذة.
- أضيفت جداول المصادقة وترحيل SQL إضافي. لم تُطبق على قاعدة PostgreSQL للمستخدم؛ اختُبرت على قاعدة محلية مؤقتة فارغة حُذفت بعد الاختبار. تعمل المسارات الفعلية فقط بعد ضبط قاعدة المستخدم وسر التوقيع في بيئة الخادم.
- أزيلت مكتبات Clerk ووسيطها غير الموصولين؛ لا يعتمد التطبيق أو الخادم على Clerk أو خدمة هوية مستضافة.
- كل مسار منشأة منفذ يتحقق من access token ثم يقرأ العضوية والصلاحية من قاعدة البيانات. إنشاء منشأة يضيف منشئها كمالك، وإضافة أعضاء تتطلب `members:manage`.
- **قرار المصادقة المعتمد:** مصادقة داخلية في API؛ لا Keycloak ولا Clerk. لا يُجهّز Ory إلا إذا طلب المستخدم لاحقًا مزود OIDC كاملًا.
- أزيل قيد العملات الثابتة والافتراضات المحددة للعملة الأساسية والضريبة وسعر الصرف وسعري التكلفة والبيع من مصدر المخطط والعقد. لم يُنشأ بعد ترحيل مرقم لهذه التغييرات، ولم تُطبق على أي قاعدة بيانات.
- المرحلة 0 غير مكتملة: نطاق الأسواق والأنشطة وإعدادات المنشأة موثق، لكن مصفوفة السياسات المحاسبية والضرائب والتقارير لكل بلد لم تعتمدها جهة مالية مختصة. لا يمكن إكمال هذه البوابة باستنتاج سياسات محاسبية.
- متطلبات المستخدم الجديدة للإعدادات والاستضافة وAPI والمصادقة القابلة للنقل موثقة في `ERP_ROADMAP_AR.md` و`ERP_SCOPE_AR.md` و`replit.md`. أُضيف API client وإعداد وقت تشغيل وفحص صحة، ومسارات ملف المنشأة والعملات والضرائب وأسعار الصرف. الربط المحمول والمزامنة، وقوائم الأسعار، وبقية وحدات ERP، و`README.md` النهائي غير منفذة.
- لم تُطبق ترحيلات على أي قاعدة بيانات للمستخدم، ولم تتغير بيانات AsyncStorage. يلزم ترحيل مرقم يحافظ على سجلات قاعدة البيانات قبل تطبيق تغييرات المخطط على قاعدة فعلية.

## الخطوات التالية المقترحة

الخطة المفصلة حسب الأولوية ومعايير القبول موجودة في `ERP_ROADMAP_AR.md`.

1. **المرحلة 0 ما زالت بانتظار اعتماد مالي:** لا تُفعّل حسابات الضريبة أو تحويل العملات أو التقارير المحلية قبل مراجعة محاسب مختص.
2. **مكتمل تمهيديًا:** أُضيف API client موحد وملف إعداد JSON لـ`API_BASE_URL` واختبار مسار الصحة. لم يُختبر اتصال فعلي بعد لأن عنوان خادم المستخدم لم يُضبط؛ لا تضف بيانات حقيقية قبل تجهيز VPS.
3. **مكتمل في 2 نوفمبر 2026:** اجتازت اختبارات الوحدة السبعة، واختبار تكامل PostgreSQL على قاعدة محلية مؤقتة وفارغة. لم تُختبر قاعدة VPS أو قاعدة مستخدمة.
4. **أُنجزت إعدادات API للمنشأة والعملات والضرائب وأسعار الصرف:** أضيف الترحيل `0003_company_business_settings.sql` ومسارات القراءة والإضافة والتعديل/التعطيل لقواعد الضرائب، والقراءة والإضافة والحذف لأسعار الصرف. هذه بيانات إعداد فقط ولا تُطبق على المستندات أو الأرصدة. لم يُطبق أي ترحيل على قاعدة المستخدم.
5. **الخطوة المفتوحة الحالية:** إكمال دورات العمل المحلية داخل التطبيق: بنود فواتير المبيعات والتحصيل الجزئي، مشتريات الموردين والسداد، وحركات المخزون المرتبطة بالقيود. لا تبدأ شاشة دخول متصلة بالخادم أو المزامنة في هذه المرحلة.
6. اعتمد محاسبيًا متى وكيف يُثبت سعر الصرف والضريبة على المستند قبل تنفيذ الحسابات، مع إبقاء السجلات القديمة كما هي.
7. أضف إدارة الفترات المالية وإقفالها واختبارات القبول المحاسبي إلى التطبيق المحلي، ثم أعد النظر في الربط بالخادم بعد اكتمال التطبيق وبموافقة المستخدم.

## نتيجة آخر دفعة تحقق

- اجتاز `pnpm --filter @workspace/midad-erp run typecheck` واختبار التخزين المعزول `pnpm --filter @workspace/midad-erp run test:storage` بنتيجة 3/3، وكذلك `git diff --check`. عاينت الشاشة الرئيسية 390×844؛ ظهرت المبالغ والعدادات بالأرقام الإنجليزية، ولم يظهر سوى إشعار React DevTools المعتاد.

- في دفعة RTL: وُحّد اتجاه النص العربي ومحاذاته على مستوى مكوّن النص المشترك، وفُعّل RTL للتطبيق، وعُدّلت الصفوف كي لا تنعكس مرتين. الحقول الرقمية والتواريخ ورموز البلدان تبقى LTR عمدًا.

- اجتاز `pnpm --filter @workspace/midad-erp run typecheck` و`git diff --check`، وأظهر إعداد Expo `supportsRTL: true`. بعد إصلاح توافق RTL مع React Native Web، عرضت معاينة 390×844 بشكل صحيح؛ لم يظهر في سجل المتصفح سوى إشعار React DevTools المعتاد.
- لم تتغير ملفات التخزين أو البيانات، وبقي مفتاح AsyncStorage `@midad-erp/local-v1` كما هو. اختبارات الحفظ المعزولة السابقة نجحت 3/3؛ لا تقرأ أو تكتب بيانات الجهاز/المتصفح الفعلية. لم يُجرَ تحقق تفاعلي على جهاز فعلي.
